# mcpbot

一台**你自己服务器**上的个人 AI 助手。

浏览器打开就能聊，模型接你自己的 Ollama，数据留在自己的机器上，之后还可以通过 MCP 接入你自己的服务。

> **不是把你的数据交给 AI，而是让 AI 来用你的数据。**

## 为什么做它

公网 AI 已经很好用了，但有些内容我不太愿意交给第三方。

聊天记录、工作内容、家庭和财务信息，甚至一些自己还没想清楚的事情。你当然可以相信服务商的隐私政策，但最终这些内容还是要进入别人的系统。

所以 mcpbot 选择了另一条路：

```text
浏览器
   ↓
 mcpbot
   ↓
自己的 Ollama
   ↓
自己的数据 / MCP Server / 自己的服务
```

模型在哪里运行、数据存在哪里、备份放在哪里，都由部署者自己决定。

这并不意味着“绝对安全”。机器、网络、反向代理、备份和访问权限仍然需要自己负责。

## 不只是一个本地聊天网页

如果只是想在本地和模型聊天，Ollama 本身已经可以解决很大一部分问题。

mcpbot 更希望解决的是下一步：

**让 AI 能够使用你自己的数据和服务。**

例如你有自己的记账系统，可以让 AI 查询：

> 这个月哪个客户欠款最多？

或者：

> 昨天服务器有没有异常？

或者：

> NAS 还有多少可用空间？

传统方式通常是先把数据导出来，再交给 AI。

mcpbot 的目标是让 AI 直接通过 MCP 调用你自己的服务：

```text
你
 ↓
mcpbot
 ↓
MCP Server
 ├── 记账系统
 ├── 项目管理
 ├── NAS
 ├── 监控系统
 └── 其他自己的 API
```

这样不需要为了问一个问题，就把整个业务系统的数据复制到第三方 AI 平台。

**不过目前的 M0 还不能实际调用 MCP。** MCP 配置部分已经预留，实际接入正在开发。

另外需要注意：MCP 本身并不保证隐私。如果模型使用的是远程 API，MCP 返回给模型的数据仍然可能发送到远程服务。真正的数据边界取决于你的模型、MCP Server 和业务数据部署在哪里。

## 数据经过哪里

mcpbot 尽量把数据路径做得简单、明确。

| 内容       | 发送到哪里                                | 保存在哪里                |
| -------- | ------------------------------------ | -------------------- |
| 聊天内容     | 你配置的推理地址，默认 `http://127.0.0.1:11434` | 你的数据目录，明文 JSONL      |
| 站点授权 Key | 浏览器 ↔ 你的服务器                          | `mcpbot.yaml`，权限 600 |
| 上游凭据     | 对应的目标地址                              | 配置目录                 |
| 业务工具调用   | 你自己配置的服务                             | 由对应服务负责              |
| 运行日志     | 默认不离开这台机器                            | `mcpbot.log`         |

目前还有几个明确的边界：

* 不内置 TLS。公网访问时，请放在自己的反向代理后面。
* 不做磁盘静态加密。
* 拿到机器磁盘的人，可以读取明文聊天记录。
* 单用户设计，没有多用户、租户隔离和管理后台。
* 不承诺医疗、法律、财务等专业结论。

自托管改变的不是“安全等级”，而是：

**原来处理这些数据的是别人，现在可以由你自己控制。**

## 当前状态

当前版本：**M0**

### 已经可用

* 授权 Key 登录
* 非流式对话
* 自动带有限的最近上下文
* 聊天历史落盘
* 网页分页查看历史
* 对话过程与结果状态记录
* 区分回答完整 / 未完成
* 区分数据已确认保存 / 未确认
* 一次对话一个名额
* 单次对话总时限，默认 180 秒
* 断线后的有界收尾
* 请求、Key、历史分页、响应大小等限制
* 启动前配置和环境自检
* 数据目录进程独占

### 还没有

* 逐字流式输出
* MCP 工具实际调用
* 长期记忆的保存、使用和修正
* 按 token 预算自动裁剪上下文
* 手机端专门优化

目前它是一个**可以实际运行的 M0**，但还不是一个完成形态的个人 AI Agent。

## 快速开始

### 前提

一台可以长期运行的机器，以及一个已经运行的 [Ollama](https://ollama.com)。

先准备一个模型：

```bash
ollama pull <your-model>
```

然后：

```bash
./setup.sh
./start.sh
```

第一次启动会打印本站授权 Key。

浏览器打开：

```text
http://127.0.0.1:8100
```

输入 Key 即可开始使用。

### 从外部访问

如果需要从其他设备访问：

1. 设置 `web.public_mode: true`
2. 使用自己的反向代理
3. 由反向代理负责 HTTPS
4. 不要直接把 mcpbot 的 HTTP 端口暴露到公网

默认工作目录为项目同级的：

```text
../mcpbot-work
```

配置、聊天记录和日志都与代码分开保存。

首次运行会根据 `mcpbot.yaml.example` 创建配置并生成随机站点 Key。Key 权限为 600，并只在首次启动时打印。

以下环境变量可以覆盖默认设置：

```text
MCPBOT_WORKDIR
MCPBOT_CONDA_ENV
MCPBOT_MODEL
```

其他配置项及取值范围见：

```text
mcpbot.yaml.example
```

## 技术信息

目前主要使用：

* Python 3.13
* FastAPI + uvicorn
* Ollama
* MCP Streamable HTTP
* httpx
* JSONL
* 服务端模板 + 原生 JavaScript
* 文件级进程锁

模型不写死：

> 推理侧交给 Ollama，mcpbot 只负责调用。

工具也不写死：

> 未来的业务能力由你自己的 MCP Server 提供。

mcpbot 不建立自己的业务数据库，也不复制一份你的业务数据。

### 项目结构

```text
src/mcpbot/
  app.py             HTTP 入口与装配
  auth.py            站点认证与入口限额
  orchestration.py   对话执行状态机、名额与预算
  ollama.py          推理接入与完成证据判定
  history.py         聊天历史保存与分页读取
  durable.py         落盘原语：追加与原子替换
  static/             前端脚本
  templates/          页面模板

docs/                 早期调研及历史材料
```

`libs/wcore` 是随仓库提供的常驻服务基础库，负责配置装载、启动核对、日志和凭据等通用能力。

代码和配置中的 `FR-xxx`、`CON-xxx`、`IF-xxx` 是需求与接口编号，用于把实现对应到项目文档。

## 如果你只是想本地聊天

那么直接使用 Ollama 或其他本地 AI 客户端可能更简单。

mcpbot 更适合这样的情况：

* 希望聊天记录留在自己的机器上
* 希望自己控制模型和数据
* 希望 AI 长期保留在自己的环境里
* 希望以后让 AI 使用自己的 NAS、项目系统、内部 API 或其他服务
* 不希望为了让 AI 处理一件事情，就先把整个业务数据导出到第三方平台

它的代价也很明确：

**你需要自己部署、更新和保护这台机器。**
