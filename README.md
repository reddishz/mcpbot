# mcpbot

跑在**你自己服务器上**的个人 AI 助手。手机或电脑浏览器打开网页就能聊，模型用你自己部署的 Ollama，工具用你自己接入的 MCP 服务——不需要第三方账号，没有订阅，聊天记录躺在你自己的磁盘上。

## 为什么要做这个

想用 AI 助手整理私密想法时，通常会遇到这四件事：

- **要先交出信息**。获得辅助的前提，是把尚未成形的草稿、私密思考和个人偏好交给一个你不掌控的服务，而且很难说清它们由谁保存、被拿去做什么。
- **每次都要重新交代背景**。你是谁、在做什么、上次聊到哪儿——换个设备或开个新会话就得重讲一遍。
- **工具本身变成负担**。要管好"会话""上下文""记忆"，你得先学会一套内部组织方式，并且持续维护它。
- **分不清建议和事实**。回答越流畅，越容易把"它给的建议"当成"它替你办好的事"。

mcpbot 的取向是：价值不体现在回答有多流畅，而体现在**你对数据的自主权、交流的连续性、对结果的合理信任**。它假定你愿意自己拥有一台机器并动手配置，用它换回前者。

## 适合谁，不适合什么

**适合**：已经有一台自己维护的服务器或家用机、愿意自己接 Ollama 的人；只想在一个私密空间里梳理想法、写草稿、延续长话题的人。

**不适合**：把它当医疗诊断、心理治疗、法律或财务建议的替代品。话题当然可以涉及健康、关系、工作或财务，但产品不承诺专业结论，也不替你判断现实决策的对错——是否采纳建议始终是你的判断。

**不是多用户产品**：一个部署对应一个使用者，认证凭一张授权 Key。不做账号体系、不做租户隔离、不做管理控制台。

## 你可以怎么用它

| 场景 | 大致是这样 |
|------|-----------|
| 梳理想法、整理草稿 | 有件不便公开或还没想清楚的事，打开网页直接说，拿到一份可以自己继续改的草稿。你清楚哪些内容只留在这台机器上。 |
| 延续话题、不用重复交代 | 上次聊到一半，下次接着聊，历史自动带出来。你也可以直接说"我家里的门锁代码是 1234""以后回答简短些"，让它沿用这些事实。 |
| 看清建议与结果的界限 | 每条回答都带着它的实际结局：完成、失败还是被中止，回答是不是完整，有没有真正存下来。远端没确认的事不会被写成成功。 |
| 接入你自己的业务工具 | 把你自己的服务以 MCP Server 的形式挂进来，让助手在对话里调用它们。 |

## 现在能做什么，还做不到

当前进度是 **M0**：认证 + 一次完整的非流式对话已经可用，其余还在路上。

**已经可用**

- 授权 Key 登录；凭据只保存在当前浏览器标签页，关掉即失效
- 即时对话，自动带上有限的最近上下文
- 聊天历史落盘保存，网页里分页往回翻
- 执行过程与结局反馈：接纳 → 生成 → 收尾 → 结束，并分别标出「回答完整 / 未完成」「已确认保存 / 未确认」
- 一次对话一个名额、一个总时限（默认 180 秒），断线后有界收尾，不排队、不失控占用
- Key 校验频率、请求体体积、历史分页与响应大小限额
- 启动前逐项自检，任一项不过直接拒绝启动并给出单行诊断；数据目录被另一进程独占时同样拒绝启动

**还没做**

- 逐字流式呈现（回答目前整段返回，事件已经是按帧推送的）
- MCP 工具接入与调用（配置段已就绪，接入逻辑未实现）
- 记忆的保存 / 使用 / 修正（能延续上下文，但不承诺长期记忆）
- 按 token 预算自动裁剪上下文与超限拒绝
- 手机端的专门排版（能打开能用，没做小屏优化）

## 快速开始

前提：一台能常驻的机器 + 一个已经跑起来的 [Ollama](https://ollama.com)（`ollama pull` 一个模型备用）。

```bash
./setup.sh    # 建 Python 3.13 环境并装依赖（有 conda 用 conda，没有退回 venv）
./start.sh    # 首次运行会打印一次本站授权 Key
```

然后浏览器打开 `http://127.0.0.1:8100`，粘贴那把 Key 登录即可。

想在别的机器上用，把 `web.public_mode` 设为 `true` 并套一层你自己的反向代理——TLS 由代理终结，本站不内置证书。

关于工作目录：`start.sh` 默认使用与项目同级的 `../mcpbot-work`，配置、聊天记录、日志都落在那里，不和代码混在一起。首次运行会按 `mcpbot.yaml.example` 生成配置、随机填入站点 Key（文件权限 600，Key 只打印那一次）。要改的东西都在那个 `mcpbot.yaml` 里，取值区间每项都写在示例的注释上；`MCPBOT_WORKDIR` / `MCPBOT_CONDA_ENV` / `MCPBOT_MODEL` 分别改工作目录、环境名和默认模型。

## 它怎么对待你的数据

- **未认证不响应业务内容。** 只有登录页和静态外壳可以匿名加载；对话、历史一律先过 Key 校验。
- **外发范围有限且明确。** 发给推理服务的只有当前输入加有限的最近上下文；凭据只在对应的认证边界使用，不会顺带附带。上游模型、地址、限额全部由你配置。
- **没有静默的告警出口。** 日志驱动的通知出站通道必须显式关闭才允许启动；启动核对发现它还开着就拒绝启动，拒绝信息走标准错误而不是日志。
- **不把没发生的事写成发生。** 上游截断、保存未确认、内部异常都会如实反映成失败或未完成，回答完整性以真实完成证据判定，不看 HTTP 200。
- **数据留在你手里。** 明文 JSONL 落在你自己选的数据目录，单进程独占写入；备份就是拷走那个目录，不需要数据库导出工具。

## 技术信息

Python 3.13 单运行时 · FastAPI + uvicorn · 服务端模板 + 原生脚本（无前端构建步骤）· JSONL 文件记录域 + 进程独占锁 · httpx 对接 Ollama `/api/chat` 与 MCP Streamable HTTP。

- 模型不写死：推理侧完全交给 Ollama，配置里只填地址与模型标识。
- 工具不写死：业务端自己实现 MCP Server，本站是通用客户端，不额外造一个 MCP 网关产品。
- `libs/wcore` 随仓库附带，是常驻服务的基础库（配置装载、启动核对、日志、凭据）；本仓库不修改它。
- 代码与配置注释里会出现 `FR-xxx` / `CON-xxx` / `IF-xxx` 这类编号，是内部需求与接口编号，用于把实现钉回对应条款。

```
src/mcpbot/        服务端
  app.py           装配与 HTTP 入口
  auth.py          站点凭据与入口限额
  orchestration.py 一次对话的执行状态机、名额与预算
  ollama.py        推理接入与完成证据判定
  history.py       聊天历史的保存与分页读取
  durable.py       落盘原语：追加与原子替换
  static/ templates/ 前端脚本与页面外壳
docs/              早期调研与已被取代的产品形态材料，仅作历史参考，不是当前设计
```
