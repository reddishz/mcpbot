# mcpbot

面向企业内部数据与流程的**自托管 AI 工作台**。

mcpbot 部署在企业自己控制的环境中：浏览器访问 mcpbot，mcpbot 连接指定的模型与业务 MCP Server；数据、凭据、访问边界和备份策略由企业自行掌控。它的目标不是把内部系统搬到一个公共 AI 平台，而是让 AI 在既有的安全边界内协助查询、分析和执行工作。

> **不是把企业数据交给 AI，而是让 AI 在企业的规则下使用数据。**

## 为什么需要它

AI 能从告警、日志、工单、报表和知识库中快速找出线索，也正因此容易越过数据边界：一次排障时上传的完整日志，可能带着令牌、客户标识或内部地址；一次看似普通的图片处理，也可能因为第三方链路或工程错误让本不该外流的数据离开控制范围。

企业真正需要解决的不是“能不能使用 AI”，而是以下问题：

* 哪些数据可以发送给哪个模型或工具？
* 推理、工具调用和结果分别经过哪些系统？
* 谁能配置连接、授予权限和审计行为？
* 一旦需要停止、迁移或删除，数据和凭据是否仍在自己手里？

mcpbot 以自托管部署和可配置的连接边界为基础，让这些问题回到企业自己的网络、权限和运维体系中。

```text
员工浏览器
   ↓
mcpbot（企业自托管）
   ├── 受控模型服务 / 本地 Ollama
   └── 受控 MCP Server
         ├── 监控与日志
         ├── 工单与项目管理
         ├── 知识库与文档
         ├── 财务、库存、CRM 等业务系统
         └── 其他内部 API
```

## 适合的企业场景

### 让排障更快，而不是让日志更容易外流

运维人员可以在企业环境中让 AI 协助归纳告警、关联现象、查询监控或调用受控诊断工具。与“复制一整段生产日志到公共聊天窗口”相比，工具只暴露完成任务所需的能力和结果，敏感字段也可以在 MCP Server 或上游系统一侧做脱敏、过滤与权限判断。

### 让业务数据按需被使用，而不是整库导出

“本月哪个客户欠款最多”“某项目有哪些阻塞项”“库存异常在哪里”，通常只需要一个受控查询，而不是把客户库、流水或项目资料批量上传。MCP 将业务能力以明确的工具接口接入；允许哪些服务、哪些工具、连接到哪里，由部署配置决定。

### 把 AI 纳入现有治理

企业可以将 mcpbot 放在内网、专有云或受控服务器中，配合已有的反向代理、TLS、网络分区、身份与权限管理、日志留存和备份制度使用。模型可以是本地 Ollama，也可以是企业批准的推理端；选择远程推理时，应将发送给模型的数据视为会离开本地边界，并据此设计脱敏与审批策略。

## 数据边界

mcpbot 不以“绝对安全”自居。它提供的是更清晰、更可控的数据路径；最终安全仍取决于部署、模型、MCP Server、网络和权限配置。

| 内容 | 默认或配置后的去向 | 责任边界 |
| --- | --- | --- |
| 聊天内容 | 配置的推理地址，默认 `http://127.0.0.1:11434` | 部署者选择并保护模型端 |
| 站点授权 Key | 浏览器与 mcpbot 服务器之间 | 配置文件 `mcpbot.yaml`，权限 600 |
| 上游凭据 | 仅发送给其对应的模型或 MCP 服务 | 配置目录与部署权限 |
| 业务工具调用 | 配置且允许的 MCP Server | MCP Server 负责细粒度鉴权、脱敏与审计 |
| 运行日志与聊天记录 | 默认保留在本机工作目录 | 部署者负责留存、备份与删除 |

部署前请特别确认：

* 不要把 HTTP 服务端口直接暴露到公网；外部访问应通过自己管理的反向代理和 HTTPS。
* 聊天记录为明文 JSONL；需要静态加密时，应在磁盘、卷或基础设施层实现。
* 远程模型、远程 MCP Server 和第三方通知通道都会改变数据边界；应按数据分级逐项评审。
* MCP 不是权限系统的替代品。每个工具仍应实施最小权限、输入校验、脱敏、审计与高风险操作确认。

## 快速开始

### 前提

准备一台可长期运行、由你控制的机器，以及一个可访问的 Ollama 服务。先拉取模型：

```bash
ollama pull <your-model>
```

然后运行：

```bash
./setup.sh
./start.sh
```

首次启动会打印站点授权 Key。浏览器访问：

```text
http://127.0.0.1:8100
```

默认工作目录为项目同级的 `../mcpbot-work`；配置、聊天记录和日志与代码分开存放。首次运行会参考 `mcpbot.yaml.example` 创建配置并生成随机站点 Key。可使用以下环境变量覆盖默认设置：

```text
MCPBOT_WORKDIR
MCPBOT_CONDA_ENV
MCPBOT_MODEL
```

其他配置项及取值范围见 [`mcpbot.yaml.example`](./mcpbot.yaml.example)。

## 产品路线图

mcpbot 的路线图围绕“企业可控地使用 AI”展开，而不是追逐一个固定开发阶段：

1. **受控连接**：持续完善模型、MCP 服务与凭据的配置边界、连接校验和故障可见性。
2. **安全编排**：强化工具白名单、调用预算、数据最小化、执行确认与可追溯记录。
3. **企业集成**：扩展与身份、审计、知识库、监控、工单及业务系统的集成方式。
4. **部署与治理**：改进生产部署、升级、备份、可观测性与组织级治理能力。

路线图描述产品方向，不构成特定功能的交付时间承诺。

## 技术信息

mcpbot 主要使用：

* Python 3.13
* FastAPI + uvicorn
* Ollama
* MCP Streamable HTTP
* httpx
* JSONL
* 服务端模板 + 原生 JavaScript
* 文件级进程锁

模型与业务工具均不写死：推理由部署者选择，业务能力由企业自己的 MCP Server 提供。mcpbot 不建立业务数据库，也不复制一份企业业务数据。

```text
src/mcpbot/
  app.py             HTTP 入口与装配
  auth.py            站点认证与入口限额
  orchestration.py   对话执行状态机、名额与预算
  ollama.py          推理接入与完成证据判定
  mcp.py             MCP 能力发现与工具调用
  history.py         聊天历史保存与分页读取
  durable.py         落盘原语：追加与原子替换
  static/             前端脚本
  templates/          页面模板
```

`libs/wcore` 是随仓库提供的常驻服务基础库，负责配置装载、启动核对、日志和凭据等通用能力。
